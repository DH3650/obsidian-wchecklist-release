# WChecklist

<img src="assets/icons/brand.svg" alt="WChecklist" width="64" height="64">

**把散落在笔记中的任务，汇总到一个可以直接操作的工作台。**

WChecklist 是一个 Obsidian 任务管理插件。你可以继续在 Markdown 笔记中记录任务，再按项目、负责人或状态集中查看、编辑和跟进。工作台中的修改会写回原笔记，任务与相关说明、链接和子任务保留在一起。

只需注册你想管理的笔记，其余普通笔记不会自动纳入。

**当前通过公有发布仓库以正式 Release 分发，提供桌面端操作与移动端工作台浏览、详情修改。** 1.0.0 将「项目分析」提升为一级导航，提供状态指标、方面分布与矩阵、负责人分布和周/月完成统计；任务详情重构为「详情／移动」两个页签，支持直接修改任务名称、删除任务与同文件/跨文件移动；勾选完成或取消时自动记录 `✅/❌` 日期。已完成 Windows 宿主与移动模拟验证，Android/iOS 真机验收与部分新功能的宿主清单回填仍待完成。日历排期、提醒和 Outlook 双向同步尚未实现。

## 它能帮你做什么

| 你的使用场景 | WChecklist 的操作方式 |
| --- | --- |
| 任务分散在多个项目笔记里 | 在「项目」工作台汇总查看，按项目、负责人、状态筛选，也可以搜索任务 |
| 想保留任务的上下文 | 查看原文层级和子任务，点击「打开原文」回到对应位置 |
| 有些事情已经交给别人处理 | 标记为「已委派等待」，设置负责人和跟进日期，在「等待」页按跟催时间等条件集中跟进 |
| 想了解项目整体进展 | 在「分析」页查看状态指标、方面分布与矩阵、负责人分布、周/月完成和异常任务，可下钻到具体任务 |
| 任务需要按主题或事务归类 | 用「方面（Aspect）」组织：一级标题或标注节点提供默认值，任务可用 `🏷️ 名称` 覆盖，并在项目页与导航树中按方面筛选 |
| 临时想到一件事，暂时不想分类 | 在「收集箱」快速新增任务，之后用「设置方面并归入项目」按目标层级选位、预览并移入项目笔记 |
| 想先看任务离里程碑目标还有多久 | 任务行 🎯 标签显示里程碑目标日期；任务没有截止日期时以虚线兜底显示；逾期显示红条与提示 |
| 不想记住每种属性的写法 | 用快捷菜单或详情面板设置优先级、日期、负责人和方面 |
| 任务行的属性标记太多 | 桌面端可用 Chip 属性标签显示并点击编辑；移动端阅读保留原始 Emoji |

## 安装

### 通过 BRAT 安装（推荐）

1. 在 Obsidian 的「设置 → 社区插件」中安装并启用 [BRAT](https://github.com/TfTHacker/obsidian42-brat)。
2. 打开 BRAT 设置，选择 **Add Beta plugin**，填入公开发布仓库地址：

   ```text
   https://github.com/DH3650/obsidian-wchecklist-release
   ```

3. 安装后，在 Obsidian 社区插件列表中启用 **WChecklist**。

后续更新可通过 BRAT 检查和安装。版本变化见 [更新日志](CHANGELOG.md)。

### 手动安装

从[公开发布页](https://github.com/DH3650/obsidian-wchecklist-release/releases)下载同一版本的 `main.js`、`manifest.json` 和 `styles.css`，放入以下目录，再在 Obsidian 社区插件设置中启用 WChecklist：

```text
<你的 Vault>/.obsidian/plugins/obsidian-wchecklist/
```

插件文件夹名称须保持为 `obsidian-wchecklist`。发布附件为上述三个文件。

## 快速上手

### 1. 写下你的第一份清单

新建一篇 Markdown 笔记，例如「网站改版」，写入：

```markdown
# 网站改版

- [ ] 整理首页需求
	- [ ] 收集参考页面
	- [ ] 确认导航结构
- [ ] 准备评审材料 📅 2026-11-06
- [>] 等待设计稿 🙋 小林 📞 2026-11-03
- [n] 评审时需要展示移动端效果
```

子任务每层使用一个实际 Tab 缩进。日期和负责人是可选属性，只有 `- [ ] 任务内容` 也可以开始使用。`[n]` 表示说明条目（Note），不会计入未完成任务数。

### 2. 把这篇笔记加入 WChecklist

保持笔记打开，从 Obsidian 命令面板运行 **WChecklist: 注册此文件到 WChecklist**：

1. 选择领域：**工作**或**个人**。
2. 选择清单类型：本例选择**项目笔记 · 面向责任人**。
3. 填写项目名称：例如「网站改版」。
4. 点击「预览注册」，检查后点击「确认注册此文件」。

注册会在当前笔记的 Properties 中保存清单信息，保留正文和已有标签；取消预览不会写入。每篇需要聚合的笔记都需单独注册。

项目类笔记有两种：**项目笔记 · 面向责任人**（`project-list`，用 🙋 标注人员）和**项目笔记 · 面向项目事务**（`project-aspect-list`，一级标题提供默认方面）。两者使用相同的领域和项目名称，就会聚合到同一个项目下。

### 3. 打开工作台，查看和修改任务

点击 Obsidian Ribbon 的 WChecklist 图标，或运行 **WChecklist: 打开任务工作台**。

在「项目」页中选择「网站改版」，点击任务查看详情。详情分为「详情／移动」两个页签：详情页可直接修改任务名称，并设置优先级、日期、负责人、方面、里程碑和状态，保存后原子写回原笔记；移动页按领域、项目、方面、笔记逐层选择位置，支持同文件调序、跨文件移动，或成为某个任务的子任务。删除任务需二次确认，执行前自动备份原文。桌面端还可用任务行的「更多操作」打开菜单。点击「打开原文」可查看对应笔记，移动端会在新的阅读标签中打开。

桌面端在原文中编辑时，把光标放在任务首行，按 **Alt+M** 打开属性菜单。快捷键可在 Obsidian 热键设置中调整。

在源码模式或实时预览中，光标位于任务首行且没有选区、只有一个光标时，按 **Ctrl+Shift+↑ / ↓** 可将任务及完整子树与相邻兄弟项交换位置。只在同一个原文列表内移动，不跨父任务、标题或独立列表；首项上移、末项下移保持原位。相邻普通列表项和 Note 也参与交换，移动后光标跟随任务。可在 Obsidian「热键」中搜索「任务上移（同层级）」／「任务下移（同层级）」调整按键；遇到热键冲突时请重新绑定。移动端不提供这两个命令。

## 日常使用

### 用五个页面组织任务

- **首页**：默认打开，汇总「下一步行动」「里程碑」「紧急事项」「跟催事项」和「待办概览」，从摘要进入详情或查看全部。
- **项目**：查看已注册清单里的任务，按工作/个人领域、项目、负责人、方面和状态缩小范围，也可以搜索。默认关注未完成任务，需要回顾时切换到「全部状态」。左侧导航按「领域 → 项目 → 方面」展开，点击方面可直接筛选。
- **分析**：从一级导航直接进入，查看具体项目的状态指标、方面分布与矩阵、负责人分布、周/月完成和异常任务。不显示筛选栏，统计全部状态，保留搜索、项目/方面导航和图表下钻；窄屏可在标题旁切换项目。与「项目」切换时保留当前项目，返回项目页恢复原筛选；从其他页面进入时在当前面板会话内恢复上次分析项目，只有一个项目时自动选中，多个项目且没有有效历史选择时提示选择。也可运行 **WChecklist: 打开项目分析** 并绑定快捷键。
- **等待**：集中查看已委派等待的任务，复用项目页的筛选工具栏，支持项目、方面、里程碑、负责人、搜索及「跟催时间」筛选（不限、未来 1 周／1 月／半年／1 年、未设跟催时间，包含逾期）；任务按项目、方面和标题路径分块展示，可切换按里程碑分组，配合负责人和跟进日期安排后续联系。
- **收集箱**：先记下任务，再整理。请先把一篇笔记注册为「收集箱」，然后在此页的「快速收集」中选择写入目标，输入内容并点击「新增任务」。整理时可在任务详情或条目菜单选择「设置方面并归入项目…」，按领域、项目、方面、笔记逐层选择位置，每层默认列出 50 项、可按需显示更多；预览方面、人员与状态变化后，追加到清单末尾或成为某个任务的最后一个子任务。取消和预览都不会改写笔记，确认后完整移动子树。

工作台保留任务的原文层级，也支持切换显示方式。桌面端移动任务时，同文件内可拖动左侧手柄调整位置；同文件调序与跨文件移动也可从任务详情的「移动」页操作，完整子树会一起移动。

桌面端的项目、等待和收集箱页，右上角新增紧凑视图图标，悬停显示「开启紧凑视图」或「退出紧凑视图」。开启后左侧项目导航保留，右侧详情栏隐藏，任务列表扩展到剩余空间；点击任务或 Note 以浮窗查看详情，关闭后回到原列表位置。再次点击图标恢复右栏。每个工作台面板独立记住模式，切换不清空筛选；有未保存详情或操作尚未完成时，请先保存、取消或等待完成。首页和移动端不提供此按钮。

### 从下一步行动开始

首页「下一步行动」推荐当前可开始、没有未结束后代的待处理任务，无日期任务也会参与。收集箱、已委派、已完成和已取消任务不参与推荐；有未完成子孙任务时，父任务暂不入列，即使子孙任务被负责人或日期条件筛掉也一样。

推荐顺序为：已逾期 → 今天截止 → 紧急 → 高优先级 → 其余。未来开始的任务通常不入列，但紧急或截止已逾期可提前出现。开始与截止均包含父任务继承值，里程碑目标日期只提供上下文，不触发行动逾期或提前入列。

部件可按部件独立配置收集范围：领域与项目、负责人范围、任务状态、日期依据（截止／跟催／两者较早）、时间窗口、无所选日期任务、有未结束后代的父任务及未来开始任务；对话框实时显示当前匹配数量，保存后同步首页、完整列表与其他面板，取消或恢复默认不写入。「跟催事项」部件同样支持按部件设置跟催时间窗口（不限、未来 1 周／1 月／半年／1 年，含逾期），未配置时沿用默认 7 天范围。

点击部件设置图标，可跳到插件设置的「特别关注」，多选或手动输入人员。留空表示关注全部，包含无负责人；填写后，只推荐生效负责人中任一人命中的任务。这一设置同时用于下方的未设截止入口，其他首页部件仍沿用各自范围。

新默认布局在顶部加入两列宽的下一步行动；已有自定义布局请在桌面端通过「添加部件」加入并保存布局。桌面与移动端均可使用部件和特别关注设置。部件默认展示前 10 条，可配置为 20／50 条；查看全部弹窗最多显示前 50 条，超过时会明确提示。

部件底部「未设截止任务 · N 条」可跳转项目页，集中查看没有自身或继承截止日期的未完成任务，包含收集箱、已委派、未来开始的任务及有未完成子任务的父任务；只有里程碑目标日期的任务仍计入。跳转会沿用关注人员与部件领域／项目范围，清除项目页旧条件，项目页完整列表不受 50 条限制。后续修改特别关注不会改变已打开的这次筛选，再次点击入口会使用最新配置。

### 自定义项目外观

在侧栏「外观设置」或插件设置页中，可为方面选择配色主题（雾色／大地／柔彩，适配明暗模式），方面颜色按名称稳定分配，也可为单个方面覆盖颜色或恢复主题默认。项目可设置内置 SVG 预设图标与预设颜色，左侧导航使用实心彩色标签，方面筛选下拉同步着色。偏好按领域与项目保存，多面板同步刷新。

### 组合项目筛选

项目页标题下直接显示筛选工具栏，桌面与移动端均可直接操作。负责人可切换「单选／多选」；多选时，任一生效负责人命中即可。

截止时间可选「不限截止时间」、近 1 周／1 月／半年／1 年，以及：

- **未设截止日期**：没有任务自身或父任务继承的截止日期；可以有关联里程碑、开始或跟进日期。
- **未设截止和里程碑**：在未设截止日期基础上，进一步排除关联了可解析且带目标日期里程碑的任务；未关联里程碑、里程碑无日期或引用无法解析的任务仍可显示。

近期范围使用任务自身或继承截止日期，包含已逾期任务和窗口末日。点击「清除筛选」可恢复常规项目列表。

### 用方面归类任务

「方面（Aspect）」用于按主题或事务给任务归类，写法仍为 `🏷️ 名称`，即原来的「类别」。默认值可来自三处，越靠下越优先：

1. **项目笔记 · 面向项目事务**的一级标题：`# 接口联调` 为其下任务提供默认方面，到下一个一级标题结束。
2. **标注节点**：标题或列表项上的 `🏷️ 名称` 供其子项继承。
3. **任务自身**：任务首行显式写的 `🏷️ 名称` 覆盖上层默认值；删除标记即恢复继承。

在任务详情、条目菜单和 Chip 中可以设置方面、选择已有方面或恢复继承；详情中还可定位默认值的来源。项目页的「方面」下拉提供「全部方面」和「未设置方面」，可与其他筛选组合；Note 不计入任务命中数。当前方面在筛选栏回显，结果区不再额外显示“方面”筛选 Chip。选择「全部方面」可清除方面条件，点击「清除筛选」可重置组合筛选。

左侧「工作／个人 → 项目 → 方面」树点击方面即可筛选。使用方面行的上移／下移按钮，或在同一项目内拖动，可调整顺序；顺序按领域和项目保存，重开后保留，新方面排在末尾。排序只影响显示，不改写笔记标题、任务内容或任务列表的物理顺序。

在文件内移动任务时，如果有效方面会变化，插件先显示变化并请求确认，确认后适应目标位置的上文，不自动补写标记。

### 在手机和平板上查看与修改

移动端以工作台查看、详情阅读和属性修改为主：

- 查看首页、项目与普通清单、等待和收集箱，使用搜索与筛选；窄屏筛选可以展开和收起。
- 点击任务打开详情弹窗，阅读内容并修改任务名称、优先级、日期、负责人、方面、里程碑和状态，点击「保存」写回原笔记；也可在二次确认后删除任务，删除前自动备份原文。说明条目（Note）与冲突条目保留只读保护。
- 有未保存修改时，返回或取消会提示确认；保存期间阻止重复提交。原文变化导致草稿失效时，请重新打开详情核对后修改。
- 阅读 Markdown 时直接显示原始 Emoji，不启用 Chip；不会覆盖桌面端保存的 Chip/Emoji 偏好。

Markdown 文件的直接编辑、原文快捷菜单与自动补全不属于移动端开发范围。任务拖动、缩进与跨文件移动、方面分配与导航排序、首页布局管理和冲突修复请在桌面端完成；移动端可临时折叠首页部件，不修改已保存的布局。

已通过桌面 CLI 和移动模拟验证布局、详情与写回。真实 Android/iOS 的软键盘、中文输入法、系统返回/手势、旋转、前后台恢复及平板分屏仍待人工验收，模拟结果不能替代这些验证。

### 用菜单设置属性

桌面端无需手写全部标记，可以从以下入口编辑；移动端请从工作台打开详情：

| 你正在做什么 | 编辑入口 |
| --- | --- |
| 在笔记里写任务 | 光标放在任务首行，按 **Alt+M**（「编辑当前条目」） |
| 想一次修改多项内容 | 运行 **WChecklist: 编辑任务详情**，或在工作台点击任务打开详情，修改后保存 |
| 已经看到属性标签 | 点击 Chip，打开对应属性菜单 |
| 想在输入时快速补充属性 | 在设置中启用「行尾空格打开快捷菜单」，在任务首行末单独输入空格 |

菜单支持优先级、截止日期、开始日期、跟进日期、负责人、方面、里程碑和状态。方面可选用已有值、输入新值或恢复继承；在收集箱任务上选择方面会打开「设置方面并归入项目…」对话框，而不是直接写入标记。常用指派人可在「设置 → WChecklist」中维护，菜单也会提供最近成功指派的人员。

使用中文输入法时，先完成选词，再单独输入空格触发菜单；按 `↓` 进入选择，继续输入会关闭菜单。

### 在原文中识别任务和属性

| 写法 | 含义 |
| --- | --- |
| `- [ ] 任务` | 未完成 / 待处理 |
| `- [>] 任务` | 已委派等待 |
| `- [x] 任务` | 已完成 |
| `- [-] 任务` | 已取消 |
| `- [n] 说明` | Note，保留说明但不作为待办计数 |
| `📅 2026-11-06` | 截止日期 |
| `🛫 2026-11-01` | 开始日期 |
| `📞 2026-11-03` | 跟进日期 |
| `🙋 小林` | 负责人 |
| `🏷️ 设计` | 方面（Aspect），即原来的「类别」 |
| `🎯 一期上线` | 关联项目里程碑，需先在里程碑清单中定义 |
| `✅ 2026-11-06` | 完成日期，勾选完成时自动记录 |
| `❌ 2026-11-05` | 取消日期，勾选取消时自动记录 |

属性写在任务首行，日期使用 `YYYY-MM-DD`。这些日期用于任务管理，目前不会创建日历事件或触发提醒。Note 可通过菜单明确转换为任务。

子任务未显式设置时，沿层级链继承最近祖先任务的 🙋 负责人、📅/🛫/📞 日期与 🎯 里程碑（逐字段取最近祖先，行内显式值优先）。继承值与显式值同口径参与负责人/里程碑筛选、日期窗口与逾期统计，工作台中以虚线弱化并附「继承自父任务」提示；这只是展示层推导，不会写回 Markdown。优先级与方面不参与此继承（方面继承规则见「用方面归类任务」）。生效截止的优先级为：任务自身 📅 > 继承 📅 > 里程碑目标日期。

在工作台勾选完成／取消，或在编辑器（Live Preview、Reading 点击 checkbox、源码模式修改）中切换已注册文件的任务状态时，插件会自动在任务行尾（Block ID 之前）补写当日 `✅`／`❌` 日期，并互清对方标记；恢复未完成或转为 Note 时移除。手工填写的日期不会被覆盖；标记与 checkbox 状态不匹配时提示诊断并保留原文。历史已完成／已取消任务没有日期时显示「未记录」，不会补造日期；未注册文件不干预。

从 0.1.8 起移除计划日期，仅保留开始、截止、跟进。旧笔记中的 `⏳ 日期` 保留原文，作为未知标记处理，不参与日期筛选、排序或继承，不生成属性 Chip，也不会自动转换为开始日期；编辑其他属性时会保留该内容。

桌面端默认的 **Chip** 显示会把属性呈现为可点击标签；光标进入属性区域时可编辑原文。偏好原始标记时，在「设置 → WChecklist → 属性显示方式」选择 **Emoji**，保存后禁用再启用插件生效。Source Mode 始终保留完整 Markdown。移动端固定使用 Emoji 阅读，保留桌面端偏好。

笔记正文中的方面属性 Chip 仅显示在「项目笔记 · 面向责任人」（`project-list`）的 Task/Note 本行显式 `🏷️` 标记上；其他类型笔记的显式方面保留 Emoji 文本，继承方面不追加 Chip。这与工作台的方面筛选控件分别控制。

### 选择适合的清单类型

注册信息保存在笔记的 Properties 中，不依赖文件名或所在文件夹。推荐通过注册命令配置；需要手工检查时，可参考：

```yaml
---
wchecklist-type: project-list
wchecklist-scope: work
project: 网站改版
---
```

| 清单类型 | `wchecklist-type` | 用途 |
| --- | --- | --- |
| 普通清单 | `general-list` | 管理日常事项，项目可选 |
| 项目笔记 · 面向责任人 | `project-list` | 按责任人与人员组织任务，注册时填写项目名称 |
| 项目笔记 · 面向项目事务 | `project-aspect-list` | 按项目事务组织任务，一级标题提供默认方面，注册时填写项目名称 |
| 收集箱 | `inbox` | 接收快速收集的任务 |
| 里程碑清单 | `milestone-list` | 定义项目里程碑，需填写项目名称 |

领域 `wchecklist-scope` 使用 `work`（工作）或 `personal`（个人）。同一个项目可以有多篇清单笔记，使用一致的领域和项目名称即可聚合查看；两类项目笔记也会进入同一项目。

面向项目事务的笔记用一级标题提供默认方面，任务可用 `🏷️` 覆盖：

```markdown
---
wchecklist-type: project-aspect-list
wchecklist-scope: work
project: 网站改版
---
# 接口联调

- [ ] 准备联调脚本 🙋 周禾
- [ ] 准备培训演示 🏷️ 用户培训
```

第一项的方面为「接口联调」，第二项显式覆盖为「用户培训」。标题须为非空纯文本；复杂标题只作结构并给出警告，不参与默认方面。

### 项目里程碑（Beta）

运行 **WChecklist: 打开项目里程碑清单**，或使用工作台项目行的 🎯 入口，打开项目对应的清单笔记。里程碑定义与改名、移动、删除目前在桌面端源文件中维护；旧的里程碑管理对话框已退役。任务可通过桌面端属性菜单选择里程碑，首行使用 `🎯 里程碑名称` 记录关联。

工作台支持按里程碑筛选和分组；首页的「里程碑」部件展示范围内全部带日期的未完成里程碑及关联任务进度，同一项目可以展示多个。支持未来一个月／三个月／半年／一年／所有，按自然月计算、月末截到目标月最后一天，包含结束日，并始终保留逾期项；无日期条目仅作数量提示。过滤选择按部件自动保存到插件 `data.json`，重开工作台或重载插件后恢复，无需点击「保存布局」。旧的独立里程碑 Dashboard 及其打开命令已退役。

桌面端首页部件正文有高度上限：自动高度最多 560px，且不超过窗口高度的一半；固定模式最多 340px，同样受半屏上限约束。超出后在部件内部滚动，标题和操作栏保留；短部件仍随内容自然收缩，刷新或调整布局时保留各部件滚动位置。移动端保持整页滚动。

里程碑带目标日期时，任务行会一并显示：🎯 标签附日期（当年显示 MM-DD，跨年显示完整日期，里程碑完成附 ✓）。任务没有自己的 📅 截止日期时，行尾以虚线弱化样式兜底显示里程碑目标日期，并在提示中注明来源；两者都有时各自显示，便于对照。项目面板中，生效截止（任务自身截止，否则里程碑目标日期）早于今天且任务未完成时，任务行显示左缘红条与红色加粗日期，提示中注明逾期天数与来源；里程碑逾期时 🎯 标签同步变红。当天到期不算逾期；里程碑已完成、任务已完成或已取消、引用未解析时都不参与逾期。任务详情面板提供只读的「里程碑目标」行，日期仍在里程碑清单中唯一维护。

里程碑功能仍在测试中，部分编辑模式、跨文件引用和多面板场景尚未完成全部实际验证；本轮新增的红条、虚线兜底与提示效果也待测试 Vault 实测回填，使用时请留意版本说明。

## 常见问题

### 为什么工作台里没有我的任务？

先确认笔记已通过「注册此文件到 WChecklist」完成注册。插件不会自动纳管普通笔记，也不会根据文件夹或文件名推断项目。

如果已经注册，先清除工作台筛选，并切换到「全部状态」。仍未出现时，打开右上角菜单中的「文件注册」检查注册状态，再查看「诊断」提示；修正 Properties 或正文问题后点击「刷新」。

### 为什么某次修改被拒绝了？

当原文已变化、多个编辑面板内容不一致，或任务标识、属性存在冲突时，插件可能拒绝写入。先核查原文和诊断，处理后重新打开菜单或详情。

如果提示保存结果未知或需要恢复，请保留相关笔记和备份，核对实际内容后再操作，避免直接重复提交。

### 为什么阅读视图里有些属性没有变成 Chip？

移动端固定显示 Emoji，不显示 Chip。桌面端 Reading 模式对富文本、重复首行、内嵌等内容可能无法可靠定位，此时会保留原生文本。可以回到原笔记编辑，或使用任务菜单；无需为了显示效果改写正文。

### 能在手机上使用，或者同步到 Outlook 吗？

移动端已加入工作台浏览、详情阅读与属性/状态/名称修改及删除，使用范围及待验项目见上文「在手机和平板上查看与修改」。目前主要在 Windows 宿主与移动模拟中验证，Android/iOS 真机、其他桌面平台及 Obsidian 历史版本未逐一验证。详细日历排期、提醒和 Outlook 双向同步属于后续计划，当前版本尚未提供。

### 禁用或卸载后，任务还在吗？

任务保存在 Markdown 笔记中。禁用或卸载后，复选框、属性标记、层级、链接和 Block ID 仍会保留；文件 Properties 也会保留。Chip 显示会恢复为原生文本。

## 更新与备份

更新前建议备份以下三类数据：

| 需要保留的位置 | 内容 |
| --- | --- |
| 你的 Markdown 笔记及目录结构 | 任务、说明、层级、属性、链接与 ID |
| Vault 根目录 `WChecklist-data/` | 独立记录、恢复日志、备份和报告 |
| `.obsidian/plugins/obsidian-wchecklist/data.json` | 显示方式、菜单开关、常用/最近指派人、首页布局与方面顺序等偏好 |

手动升级时，禁用插件，只替换同一版本的 `main.js`、`manifest.json`、`styles.css`，保留 `data.json`，再重新启用。不要通过删除整个插件目录来升级。

任务索引会在启动或工作台「刷新」时从笔记重新构建；`WChecklist-data/` 中的独立记录与恢复证据不能当作缓存删除。单独复制一篇 Markdown 不等于完整备份。
